## Notes Directory

Purpose: AI-managed knowledge base on the project. Foundation for later formal requirements + business logic.

## Content Nature

Notes = author's evolving thinking. Speculations, wonderings, open questions → over time harden into decisions. Track this progression. Mark status (open thought vs settled decision) so later readers know what's final.

## Agent Responsibilities

- **Capture**: write down author thoughts + decisions. Agents responsible for recording, not author.
- **Organize**: keep dir well-organized. Over time → split, combine, move, or fully reorganize docs as content grows.
- **Hierarchy**: agents authorized to manage any subdir hierarchy under `notes/`. Create/restructure freely.

## index.md

`notes/index.md` MUST exist. Describes current organization structure of notes.

- Reflects real layout: dirs, files, what each holds.
- Refactor encouraged → when structure changes, update `index.md` to match.
- Read `index.md` first → understand current org before adding/moving notes.

## End Goal

Notes mature → basis for writing formal requirements + business logic. Keep that target in mind when capturing + structuring.
